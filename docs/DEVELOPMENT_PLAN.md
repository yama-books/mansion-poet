## 0. 基本方針と完成像

日本全国で任意の地点を選ぶだけで、その地点に関係する**検証可能な地理・施設の特徴**を抽出し、**高級マンション広告として異様なほど真剣かつ格調高い創作文**へ仕立てる。UIは高級レジデンス公式サイト風の洗練を貫く。

最大の価値は「APIの件数」ではなく、次の三項：
1. **固有性**：別の街では成立しない描写が1箇所以上ある。
2. **文章の完成度**：見出し・本文・架空物件名がひとつの主題で響き合う。
3. **軽さと信頼**：場所選択から完成まで迷わず動き、施設名と創作表現を取り違えない。

ユーモアはビジュアルではなく、過剰に荘厳な言葉と現実的な立地・施設との落差から生む。「マンション広告の広告らしさ」を真面目に再現しつつ、実在の分譲物件、資産価値、眺望、徒歩距離を断定しない。

### 大原則

- **公開は GitHub Pages、基本機能はブラウザ内で完結**。個人APIキーをフロントに置かない。
- **データと創作を分離**。真偽の根拠・取得元・取得状態を作品の下で確認できる。
- **元の動く体験を壊さない**。小さな変更をPR単位でレビュー、検証してから main へ取り込む。
- **独自に設計された豪華さ ≠ 重い技術構成**。使い続けられる軽量さを守る。
- **AIは必須にしない**。まずは規則・辞書・構文・地域特徴評価を強化する。
- ユーザーへの提供状態を「実装済／モックテスト済／実ブラウザ検証済／実機検証済」に分ける。

## 4. v0.2：高級マンション広告の完成度を引き上げる

詳細は [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) を正本とする。

- **画面構造**：「導入ビジュアル → 場所検索／地図 → 生成結果 → 生成根拠」の4節。地図と作品を切り替えて表示するより、ユーザーの現在地（進行状態）を明示して縦の導線を磨く。
- **情報の主従**：場所・生成ボタン・見出しを最も目立たせる。経緯度や施設一覧は控えめな情報の層へ収める。
- **モバイル**：初期の巨大ヒーローで主要操作が遠くならないよう、ファーストビューに「この場所を選ぶ」導線を置く。片手で入力、候補選択、生成まで到達できる。
- **マイクロモーション**：大きな見出しは短いフェード・スライド、物件の言葉や細い線だけが時間差で登場。左右の箱が過剰に飛ぶ演出は避け、reduced-motionへ対応。
- **文章品質の速効改善**：同じ地点でも最低5案を生成可能にし、語尾や構文だけでなく主題・視点・見出しも変える。
- **低濃度・高濃度**：濃度0は少し上品な紹介文、50は不動産広告、100は抽象性が高い詩文。情報を捏造する度合いではない。
- **細部**：フォーカス枠、44px相当のタップ領域、地名検索結果のキーボード操作、ローディング／失敗／完了状態を追加する。

2. 位置検索から生成・コピーまで初見利用者が説明なしで完了可能。

## 5. v0.3：土地の解釈エンジン

地理ソースの拡充は**必要性から逆算**する。最初から全データを収集しない。

### 地点解析のパイプライン

\`\`\`text
Location（確定地点、名称、lat/lon）
  ├─ GSI：地名・（追加時）標高／地形
  ├─ OpenPOI：商業、教育、文化、交通などのPOI
  └─ OSM/Overpass：公園、水辺、史跡などの補足
         ↓
NormalizedEvidence（事実候補と出典）
         ↓ 住所・距離・カテゴリ・重複・鮮度評価
LandSignals（文教・歴史・都市性・自然・日常ほか）
         ↓ スコアリング + 単一施設への過剰依存を防ぐ
ThemePlan（主題、補助主題、確かな固有名詞、避ける表現）
         ↓
PoemEngine → PropertyName / Headline / Body / Evidence
\`\`\`

### 地域スコアの初期案（確定値ではない）

- 文教、文化、歴史、緑、水辺、都市・交通、商業、日常の**8軸**。
- スコアは「施設の個数」だけでなく、施設カテゴリの信頼度、中心からの距離、独立した施設の数、ソースの一致、地理的多様性を使用する。
- 例：各シグナルの重み = 分類信頼度 × 距離減衰 × 独立性係数 × ソース品質係数。小さい施設多数で一つの特徴が独占しないよう対数圧縮と上限を設ける。
- 閾値未満なら**不確かな地域特性を無理につけず**、地名と一般的な言葉で詩を書く。
- 都心と地方・離島ではPOI密度が異なる。半径は固定850mを基準に、施設密度に応じた段階（例：850m → 1500m → 3000m）を**画面に明示して**追加調査する案を比較検証する。距離はあくまで直線距離、徒歩所要時間には変換しない。
- 一つの主題と補助主題は原則別系統。例：「文教＋歴史」「水辺＋都市」「緑＋日常」。
- 重要事実は「採用」「要確認」「棄却」を分離する。生成文には採用だけを使う。

### 出典情報

NormalizedEvidence推奨項目：
\`\`\`text
id, source, sourceId?, name, category, lat, lon,
distanceMeters, address?, attributes?, license[], attribution[],
retrievedAt, confidence, validationFlags[], themeTags[]
\`\`\`

※「confidence」は**アプリが付けた分類・位置一致の推定値**であり、施設の実在確認を保証しない。UIは「取得データ」「創作表現」「未確認」を区別する。

### v0.3完了条件

- 16以上の代表地点でデータの偏りを点検。都市・住宅街・山間部・海沿い・離島を含む。
- データが取得できた地点について、地域を特徴づける根拠が少なくとも1つ説明できる割合を測定し、目標85%以上。
- 位置矛盾・固有名詞に関する危険な言い換えを0件にすることを狙う。
- 地理ソースの追加に伴う初期表示性能の顕著な悪化なし。

## 6. v0.4：マンションポエムの文芸エンジン

詳細は [GENERATION_ENGINE.md](GENERATION_ENGINE.md) を正本とする。

### 生成する4層

1. **論旨（ThemePlan）**：何を褒めるか。例「文教」「地の記憶」「都市の交差」「森の余白」。
2. **比喩の変換（Lexicon）**：文教→「知の集積」「叡智」など、歴史→「記憶」「継承」など。無関係な語は使わない。
3. **文章設計（Composition）**：見出し・導入・具体的な地名／施設との接続・抽象化・余韻。
4. **広告への仕立て（Art Direction）**：架空物件名、英語名、見出しの改行、文章長、濃度。

### 文体と濃度

既存の3文体（Heritage / Metropolis / Sanctuary）をまず深める。追加するなら将来「文教」「水辺」「極限の抽象」等を実験するが、操作項目を無闇に増やさない。

濃度は0～100で5段階の内部プリセットに正規化して設計し、スライダーは維持：
0–20 誠実で控えめ、21–40 端正、41–60 王道広告、61–80 壮大、81–100 過剰な荘厳さ。数値は文章の抽象度・修飾度・文体の格に影響する。**事実を作る強度ではない**。

### 禁則

- 実在物件がある、駅徒歩○分、眺望保証、静寂保証、資産価値上昇を示唆しない。
- 特定学校や宗教施設の存在だけで「名門」「格式」「住民の属性」などを断定しない。
- 名前から確定しない歴史、自然、文化的事実を生成しない。
- 同じ言葉・定型句を短時間に過剰に重複させない。
- 初回出力と再生成を seed / version で再現可能にする。画像やリンク共有に向け、選択した文体・地点・バージョンを保持。

### v0.4完了条件

- 同一地点5案で、見出しの単純置換ではなく**主題・構文の違い**が少なくとも3案。
- 3文体×5濃度段階×代表地点で、文体や濃度の違いをレビューで識別できる。
- 本文に採用した固有名詞は、必ずEvidenceに追跡できる。
- 単語連結で生じる不自然な助詞、文字種、繰り返し、過剰な句読点の回帰テストが通る。

## 7. v0.5：架空マンション広告の作品化

- **広告テンプレート2種のみから開始**：
  - Editorial（深緑・文字中心。大きな余白、書籍の表紙のような構成）
  - Architecture（建築SVGを使う。極細グリッドと巨大な見出し）
- 「架空物件名／主見出し／本文／地名／小さな創作注記」の文字組みを統一。
- **保存はPNGを優先**。可能なら2倍解像度、できなければ通常解像度とする。印刷は既存CSSを継続。外部写真の取得・画像生成APIは当面利用しない。
- Web Share APIがあれば共有、なければ画像保存・コピーへフォールバック。
- 長い地名、極端に長い施設名、縦横比、フォント未読込でも文字が切れない。
- 注記と必要な出典を画像内・付属説明へ入れる方針をライセンス確認後に確定。
- 新しい重い描画ライブラリを入れる前にSVG・Canvas・DOM描画のサイズとSafari動作を比較する。

### v0.5完了条件

- iPhone Safari と主要デスクトップブラウザで広告画像を作成・保存できる。
- 3文体×2テンプレートで違和感のない画面と画像。
- 作品画像に実在物件と誤認させない注記がある。
- ファイル名はASCII安全なprefix＋日付またはseed。個人情報を含めない。

## 10. 作業管理と意思決定

1PR = 原則ひとつのユーザー価値または不具合修正。ファイルの大量書換え・機能追加・デザイン変更・デプロイ改修を一気に混ぜない。

**各PRに必要なもの：**
- タスクID、現象または狙い、変更範囲、影響しない範囲。
- before / after（UI変更時はPCとモバイルのキャプチャ）。
- テスト実績（自動／手動／公開ブラウザを別記）。
- 取得API・ライセンス・アプリの重量増への影響。
- ロールバック方法。mainへの取り込みをゴールとし、CI失敗を無視しない。

**優先順決定**：利用不能・誤事実・公開障害 ＞ 地名操作・スマホ ＞ 文章品質 ＞ タイポグラフィ・モーション ＞ 新規モード・周辺機能。

**不具合レベル**：P0 = 公開不能／主要機能不能／誤情報の断定、P1 = 操作継続可能だが機能・信頼が損なわれる、P2 = 軽微な見た目や特定条件の不具合。

**ソースの正本**：
- 本ファイル：マスタープラン
- [ROADMAP.md](ROADMAP.md)：実装・テスト状態の短い一覧
- [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)：ビジュアル・インタラクション
- [GENERATION_ENGINE.md](GENERATION_ENGINE.md)：文章アルゴリズムと品質評価
- [QUALITY_TEST_PLAN.md](QUALITY_TEST_PLAN.md)：テストケース・判定
- [DATA_SOURCES.md](DATA_SOURCES.md)：API・出典とデータの制約
