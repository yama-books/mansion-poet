# SELECT-01｜証拠IDと広告主役の一元化

2026-10-17 JST / APP-003 / POÈME / ESTATE

## 背景

GEO-02の限定検索はコードとfixture/CIまで実装されたが、実OSM要素のライブ取得は公開Overpassの500/502で未検証。そこでAPIを無限に再試行せず、**POEM主役・LOCATION先頭・THE EVIDENCE**の接続を改善し、どの地物が広告に使われたか追える構造を先行整備する。

## 実装範囲

- 既存の施設選択順序、SAFE-01の許可ゲート、POEM辞書630フック、LOCATION広告117組は再利用。
- `buildThemePlan` は、同じランキングから一度だけ既存LOCATIONカード最大3枚を構築し、その先頭の出典IDをポエム主役とする。副題は2件まで。
- ThemePlan概念フィールドは `mainEvidenceId`, `secondaryEvidenceIds`, `locationCardIds`, `genreId`, `poemPOIs`, `locationCards`。外部入力の出典IDが欠ける場合、source/name/座標から**内部参照専用**のキーを作る。出典IDを創作していないことを明確にする。
- LOCATIONを1回構築して表示へ渡すため、先頭カードの再計算による変化を避ける。
- カードが0枚なら従来の地域テーマ候補を保持し、地名のみの創作まで退行させない。
- THE REALITYは独立した元POIの検証と生活分類を維持。所在地・徒歩距離・経路・ブランド・歴史の創作なし。
- 回帰は構造化Planの同一ID、実際の描画結果の主役整合を代表2ケースで確認。28ケースの全面再検証はしない。

## 進捗の扱い

13段階を等重みに換算するマクロ計画では、PLAN/SAFE/GEO-01=各1、GEO-00/GEO-02/SELECT-01=各0.5として本PRのCI完了時に `(3+0.5+0.5+0.5)/13≈35%`。選択工程は、出典契約→コード→fixture/CI→公開ブラウザ受入の4ゲートとし、CI合格段階のミクロは最大75%。**数字は工数や残り時間の測定値ではない**。
