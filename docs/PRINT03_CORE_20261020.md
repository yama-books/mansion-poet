## 2. PresentationData（schema `print03.v1`）

```js
{
  generationToken: 'gen-…',             // 必須。COPY-LOCK-01 の世代。render(…,{expectedToken}) 不一致なら H-07 で拒否
  place:    { label: '神保町', en: 'JIMBOCHO' },
  property: { name: 'THE JIMBOCHO RESIDENCE', serial: '001' },
  poem:     { headline: '知の深奥に、\n邸の答えを。', body: '…\n…' },
  mainSubjectId: 'node/123' | null,     // LOCATION がある場合 locations[0].sourceId と一致必須（SELECT-01）
  locations: [ /* 0..3 */ { rank, sourceId, name, genreLabel, address, addressPrecision: 'full'|'street'|'area',
                distanceMeters, walkMinutes: null, routeVerified: false, headline, body,
                source: 'OSM'|'OpenPOI', retrievedAt: 'YYYY-MM-DD' } ],
  evidence:  { mode: 'poi' | 'place_only' },
  colorMode: 'color' | 'mono',
  outputMode:'ConsumerPDF'               // それ以外は拒否（PDF/X 未実装）
}
```

検証で**拒否**するもの：トークン欠落（H-07）、LOCATION 4件以上、LOCATION 01 と主役の不一致（SELECT-01）、距離の欠落・負値（H-02）、`routeVerified` なしの徒歩分（H-03）、`price`・`floorPlan`・`phone`・`seller` 等の販売情報風フィールド（H-08）、`place_only` なのにカードあり、出典が OSM/OpenPOI 以外。

住所表記・距離表記・出典表記は index.html の `formatLocationAddress` と同じ文言を再現（`所在地（地域情報のみ）：…` 等）。

クレジットは**実際に印刷する要素から**合成：創作注記（常時）、線画注記（線画を使う版型）、施設データ注記＋出典別の取得日（カードありの場合）、地名のみ注記（0件の場合）、模式図注記（location版型でカードありの場合）。0件では空のLOCATION枠も距離注記も印刷しない。

## 3. 安全な出力

- テンプレートは `{tag, attrs, children}` の木を作るだけ。データ文字列は必ずテキストノード。
- `toDOM` は `createElement` + `textContent` 相当、`toHTML` は全テキスト・属性をエスケープ。
- 属性は許可リスト方式、`on*`・`href`・`src`・`style` 等はシリアライザが例外で拒否（データ由来でなくても）。
- F07 fixture（`<script>`、`<svg onload>`、`javascript:` 等）が3版型すべてで文字として印刷されることをNodeとPDFテキスト層の両方で確認。

## 4. 改ページ（A4一枚優先・表裏構成・文字は削らない）

**2026-10-20 ユーザー決定**：読みやすさ基準よりも実際のチラシに近い詰め込み感を優先し、A4一枚を最優先、収まらない場合は表裏構成とする。

文字サイズの扱い（[AD QUALITY GATES §6](AD_QUALITY_GATES_V1_20261019.md) の「注記は可能な限り8pt以上」からの意図的な変更）：
- 住所・出典・注記・キャプションなどの細字（物件概要風の部分）：基本7.5pt、fit 3で7pt、fit 4で**6.5pt下限**。注記は実際の広告の物件概要欄のように2段組。
- 創作注記（「物件と広告文章は創作です…」）と全ページ下部の柱：**8pt下限を維持**。誤認防止のハードゲート H-01 のための例外で、`verify()` が個別に検査する。
- ポエム本文・カード本文などの主文は8pt以上（fit 4で本文8pt、ポエム10pt）。

手順：
1. 印刷DOMにブロック（masthead / hero / poem / locations / notes）を流し込み、`getBoundingClientRect` で実測。
2. **A4一枚**：fit level 0 → 1（余白・見出し29pt）→ 2（補助カード2列化）→ 3（細字7pt）→ 4（見出し24pt・細字6.5pt）。
3. **表裏構成**：一枚に収まらなければ、表面＝広告（見出し・ポエム・物件名・主役カード全文・補助カードは名称／直線距離／ひと言＋「所在地・紹介文・出典は裏面」・創作注記と裏面案内）、裏面＝LOCATION DATA（補助カードの全文）＋全注記・出典。各面をそれぞれ fit 0〜4 で一枚に収める。柱は「表面 1 / 2」「裏面 2 / 2」。
4. **最終手段**：表裏でも収まらない場合（例：22行の長文ポエム）のみ、行・カード・注記行の単位で複数ページへ続ける。続きには「（前頁より続く）」。
5. `verify()` が欠落文字列（表裏・複数ページの全体で照合）・縦横はみ出し・ブロック重なり・細字6.5pt下限・創作注記8pt下限・各ページの創作注記・表面の創作注記・最終ページの注記をチェック。

QAで検出して修正した不具合：ページ番号を後から入れると柱が伸びて本文が2.2pxはみ出す件（verifyが検出。計測時にプレースホルダ番号を入れて解決）、location版型の縦組み見出しが長い英字で溢れる件（verifyが検出。縦組みは短い和文見出しに限定）、続きのカードを判定するカウンタの誤りでページ1が半分空になる件（PNG目視で検出）。

## 6. 3版型の比較（目視所見）

`tests/print-layout/samples/compare-sheet-*.png`（fixture毎に3版型を並置）。

- **type_poem（完成）**：大きな明朝見出し＋余白＋自作アーチ線画。主役カードは淡い地色で強調、補助2件は帯（fit 2以降は2列）。注記は物件概要欄風の2段組の細字。標準の3件・長い名称・長い紹介文まで1枚に収まり、0件でも空枠なしで紙面が成立。白黒でも主役の区別が枠線で残る。写真がなくても成立し、画像納品を待たずに使える最初の印刷試作として適格。
- **editorial（骨格）**：上部の架空建築線画（主図版約30%）→中央揃えの詩→3列カード。図版が入ると最も「高級誌面」らしいが、3列のため長い住所・名称で行数が増えやすく fit 3 に頼りがち。IMG-00 の print_hero 受入後に本格化。
- **location（骨格）**：模式図（縮尺・方位なし、距離は半径の相対のみ）＋縦組み見出し＋主役大カード。模式図の分だけ高さを使うが、細字化で標準3件は1枚に収まる。長い紹介文では表裏になる。位置図の正確性（H-02/H-03）と模式図注記の扱いを優先して詰める必要あり。

   ```js
   if(!generatedCurrent)return;
   const data=PrintPresentationData.fromAppSnapshot({generationToken:'v'+generationVersion, place:selected,
     propertyName:$('#poemProperty').textContent, headline:…, body:…, mainEvidenceId:…,
     locationCards:lastLocationCardItems, verified:…});
   ```
