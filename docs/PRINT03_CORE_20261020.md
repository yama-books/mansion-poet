  place:    { label: '神保町', en: 'JIMBOCHO', lat: 35.6959, lon: 139.7577 },   // lat/lon は任意（位置関係図用）

  mainSubjectId: 'node/123' | null,     // LOCATION がある場合 locations[0].sourceId と一致必須（SELECT-01）
  locations: [ /* 0..3 */ { rank, sourceId, name, genreLabel, address, addressPrecision: 'full'|'street'|'area',
                distanceMeters, walkMinutes: null, routeVerified: false, headline, body,

  outputMode:'ConsumerPDF'               // それ以外は拒否（PDF/X 未実装）

検証で**拒否**するもの：トークン欠落（H-07）、LOCATION 4件以上、LOCATION 01 と主役の不一致（SELECT-01）、距離の欠落・負値（H-02）、`routeVerified` なしの徒歩分（H-03）、`price`・`floorPlan`・`phone`・`seller` 等の販売情報風フィールド（H-08）、`place_only` なのにカードあり、出典が OSM/OpenPOI 以外。

住所表記・距離表記・出典表記は index.html の `formatLocationAddress` と同じ文言を再現（`所在地（地域情報のみ）：…` 等）。

クレジットは**実際に印刷する要素から**合成：創作注記（常時）、線画注記（線画を使う版型）、施設データ注記＋出典別の取得日（カードありの場合）、地名のみ注記（0件の場合）、位置関係図注記または模式図注記（図を印刷する場合のみ）。0件では空のLOCATION枠も距離注記も印刷しない。

### 2.1 位置関係図（裏面・location版型）

**2026-10-20 ユーザー要望**：裏面に、選択地点と施設の関係が分かる美しい図面を置く。

- 選択地点と各施設の緯度経度だけから作図する。北が上・実縮尺、距離の同心円（R/4・R/2・R、Rは最遠施設に合わせた切りの良い値）、縮尺バー、方位記号、選択地点から各施設への直線（主役01は実線、補助は点線）、番号マーカー。凡例に番号・種別・施設名・直線距離。
- **地図タイル・道路・経路は描かない**（印刷層は通信しない。経路に見える線を引かない＝H-03）。注記：「位置関係図は選択地点と施設の座標から描いた参考図です。距離の円と線は直線距離を示し、道路・経路・徒歩時間・施設の敷地範囲を示すものではありません。地図データは使用していません。」
- **座標から計算した距離が印刷する「直線 約○m」と食い違う場合（±25m または ±15% 超）は図を描かない**（H-02：誤った位置の断定を避ける）。座標がない場合も描かない。validate() は警告を返し、location版型は従来の「模式図（縮尺・方位なし）」へ戻る。
- `render(id, data, {sheet:'duplex'})` で、A4一枚に収まる場合でも表裏で出力できる（裏面＝位置関係図＋補助カード全文＋注記）。既定は `auto`（一枚優先、収まらなければ表裏）。

### 2.3 周辺の施設（裏面の番号付き一覧）

**2026-10-21 ユーザー決定（A案）**：実際の広告は「表で数件を写真付きで魅せ、裏・地図で多数を列挙する」構成が一般的（件数は本リポジトリの広告調査では未計測。一般知識として、チラシ表面の周辺環境写真は数点、ロケーションマップは10〜30件以上が多い）。そこで表面の紹介文付きカードは3件のまま、裏面の地図と凡例に**周辺の施設を最大7件**（LOCATION 01〜03に続く04〜10）追加する。魅力的な施設が並びつつ、さほど魅力でもない施設も自然に混ざる仕上がりにする。

- `src/print-layout/neighborhood.js` の `curate(pois, {subjectPolicy, exclude, firstRank})`：アプリが取得・正規化済みのPOI（index.html `normalizePOIs` の出力）から選ぶだけの純粋関数。通信・新しい事実の生成はしない。
- 対象：半径850m以内、`classificationConfidence:'high'`、分類の衝突・未検証フラグなし、`SubjectPolicy.decideSubject()` が allow。LOCATIONカードと同じ施設は除外。
- **魅力枠**：テーマ別スコア（緑9・水辺/歴史/文化8・知7・交通6・商業/日常5・飲食4）＋名称あり＋近さで並べ、同じ種別は2件まで。
- **さほど魅力でもない枠**：郵便差出箱・マンホール・カーブミラー・側溝/暗渠・自販機・宅配ロッカー等（明示タグのみ）。7件中2件まで、同じ種別は1件まで、魅力枠の約半分以下（最低1件）。末尾にまとめず3番目・6番目に混ぜる。どちらの枠かは紙面に出さない。
- **医療機関（2026-10-21 ユーザー決定）**：病院・診療所・歯科・薬局は利便性の情報として**一覧に限り1件まで**掲載（POEM・紹介文付きカードでは従来どおり主題にしない）。名称・種別・直線距離のみで紹介文は付けない。福祉・介護・ホスピス・精神保健・依存症・リハビリ等は除外（名称に「心療」「精神」等を含むものも除外）。さほど魅力でもない枠には入れない。掲載時の注記：「医療機関は名称と直線距離のみを掲載しています。診療科目・受診可否・診療時間は掲載していません。利用前に各機関へ確認してください。」
- 紙面：位置関係図に小さな番号マーカー（直線は引かない）。地図の横に01〜03と04〜の凡例を1列にまとめる。注記に「『周辺の施設』は取得できた公開データから選んだ一部で、地域のすべての施設や評価・おすすめ順を示すものではありません。」、出典に該当データの取得日。
- 座標と距離が食い違う施設・座標のない施設は一覧から外す（警告のみ、図は描く）。一覧は裏面の地図に付くため、表裏で出力するときだけ印刷する（A4一枚で出力する場合は載らない）。

#### 探索範囲・条件の精査（index.html への提案、本PRでは未変更）

現状（`index.html`）：OpenPOI は半径850mで2クエリ（無指定180件、文化系キーワード100件）。OSM 補完は OpenPOI の結果が4件未満・緑なし・自然モードのときだけ（公園・図書館/大学/学校・史跡・博物館/美術館・駅・水面・河川、最大12件）。小さな都市設備（郵便差出箱・マンホール・カーブミラー・暗渠・側溝）は**利用者がオプトインしたときだけ**半径450mで取得。THE REALITY（生活施設）はOSMの店舗を取得していないため、買い物系が空になりやすい（LIFE-01記録で中野は0件）。

周辺の施設一覧を充実させるための提案（担当調整のうえ別PR）：
1. **印刷用の取得**：表裏印刷を選んだときは OSM 補完を常に実行し、`shop=supermarket|convenience|books`、`amenity=post_office|pharmacy|hospital|clinic`、`leisure=playground|garden`、`tourism=viewpoint` を追加（いずれも明示タグ、半径850m、件数上限つき）。
2. **小さな都市設備**：表裏印刷時は既定でオプトイン扱い（半径300〜450m、最大20件）。近いほど「さほど魅力でもない施設」の混入感が出る。
3. **半径**：魅力枠は850m（現状維持）、都市設備は450m以内。距離はすべて直線距離のまま（徒歩換算しない）。
4. **受け渡し**：生成完了時に正規化済みPOI一覧と座標を `fromAppSnapshot({..., neighborhood: PrintNeighborhood.curate(pois, {subjectPolicy: SubjectPolicy, exclude: cardIds, firstRank: cards.length+1})})` で渡す。

### 2.2 地図（国土地理院タイル）

**2026-10-20 ユーザー決定**：地図を入れる。ポエムを楽しむと同時に、住むかもしれない場所の環境を調べる道具としても使えるようにする。

- 位置関係図の下に、アプリ本体と同じ**地理院タイル（淡色地図 `xyz/pale`）**を敷く。選択地点を中心に Web メルカトルのタイル座標を計算し、同心円・直線・マーカーと同じ縮尺・中心で重ねる。ズームは最大16（淡色地図は17以上で注記文字が大きくなり、紙面上の情報量が増えないため）。地図を敷くときは**半径400m以上**の範囲を表示（近い施設だけだとタイルが拡大されすぎ、文字が巨大にぼやけるため。周辺環境を見る用途にも合う）。タイル数は試験データで9〜12枚。
- 指示書の「描画レイヤーに通信を持ち込まない」との関係：`render()` は今も通信しない。地図は `render(…,{mapTiles:'gsi-pale'})` または `PrintPaginate.mountWithMap()` を明示した場合だけ。出力できるURLは `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`（整数のみ）に限定し、シリアライザが他のURL・他のタグの `href` を拒否する。データ文字列からURLは作られない。タイルの取得で外部に伝わるのは地図の範囲（選択地点のおおよその位置）で、アプリ本体の地図表示と同じ。
- `mountWithMap()` は全タイルを先読みし、**1枚でも失敗・タイムアウトしたら地図なしの位置関係図に切り替える**（部分的な地図を印刷しない。地図の出典も載せない）。
- 地図使用時の注記：「位置関係図は国土地理院の地図に、選択地点と施設の座標から直線距離の円と線を重ねた参考図です。道路・経路・徒歩時間・施設の敷地範囲を示すものではありません。」
- **出典は末尾に集約**（ユーザー決定 2026-10-21）：注記ブロックの最後に「SOURCES / 出典」として、施設データ（OpenStreetMap／OpenPOI と取得日）と地図（「地図：国土地理院『地理院タイル（淡色地図）』を加工して作成」）をまとめて表示し、分割されない1単位として最終ページに置く。図のキャプションは「地図の出典は末尾に記載」とだけ示す。
- 地図の配色は紙面に合わせて彩度を落とし、紙色を薄く重ねる。白黒印刷ではグレースケール。
- **利用前提（ユーザー決定 2026-10-21）**：印刷機能は**個人向け**（利用者が自分でPDF化・印刷して閲覧する）とし、地理院タイルは出典明示のうえ利用する。印刷物を配布・刊行する用途は想定しない。将来その用途を加える場合は、国土地理院の利用手続き（測量法に基づく承認等）の要否を改めて確認する。

## 3. 安全な出力

- テンプレートは `{tag, attrs, children}` の木を作るだけ。データ文字列は必ずテキストノード。
- `toDOM` は `createElement` + `textContent` 相当、`toHTML` は全テキスト・属性をエスケープ。
- 属性は許可リスト方式、`on*`・`href`・`src`・`style` 等はシリアライザが例外で拒否（データ由来でなくても）。
- F07 fixture（`<script>`、`<svg onload>`、`javascript:` 等）が3版型すべてで文字として印刷されることをNodeとPDFテキスト層の両方で確認。

## 4. 改ページ（A4一枚優先・表裏構成・文字は削らない）

**2026-10-20 ユーザー決定**：読みやすさ基準よりも実際のチラシに近い詰め込み感を優先し、A4一枚を最優先、収まらない場合は表裏構成とする。

文字サイズの扱い（[AD QUALITY GATES §6](AD_QUALITY_GATES_V1_20261019.md) の「注記は可能な限り8pt以上」からの意図的な変更）：
- 住所・出典・注記・キャプションなどの細字（物件概要風の部分）：基本7.5pt、fit 3で7pt、fit 4で**6.5pt下限**。注記は実際の広告の物件概要欄のように2段組。
- 創作注記（「物件と広告文章は創作です…」）と全ページ下部の柱：**8pt下限を維持**。誤認防止のハードゲート H-01 のための例外で、`verify()` が個別に検査する。
- ポエム本文・カード本文などの主文は8pt以上（fit 4で本文8pt、ポエム10pt）。

手順：
1. 印刷DOMにブロック（masthead / hero / poem / locations / notes）を流し込み、`getBoundingClientRect` で実測。
2. **A4一枚**：fit level 0 → 1（余白・見出し29pt）→ 2（補助カード2列化）→ 3（細字7pt）→ 4（見出し24pt・細字6.5pt）。
3. **表裏構成**：一枚に収まらなければ、表面＝広告（見出し・ポエム・物件名・主役カード全文・補助カードは名称／直線距離／ひと言＋「所在地・紹介文・出典は裏面」・創作注記と裏面案内）、裏面＝LOCATION DATA（補助カードの全文）＋全注記・出典。各面をそれぞれ fit 0〜4 で一枚に収める。柱は「表面 1 / 2」「裏面 2 / 2」。
4. **最終手段**：表裏でも収まらない場合（例：22行の長文ポエム）のみ、行・カード・注記行の単位で複数ページへ続ける。続きには「（前頁より続く）」。
5. `verify()` が欠落文字列（表裏・複数ページの全体で照合）・縦横はみ出し・ブロック重なり・細字6.5pt下限・創作注記8pt下限・各ページの創作注記・表面の創作注記・最終ページの注記をチェック。

QAで検出して修正した不具合：ページ番号を後から入れると柱が伸びて本文が2.2pxはみ出す件（verifyが検出。計測時にプレースホルダ番号を入れて解決）、location版型の縦組み見出しが長い英字で溢れる件（verifyが検出。縦組みは短い和文見出しに限定）、続きのカードを判定するカウンタの誤りでページ1が半分空になる件（PNG目視で検出）。

## 6. 3版型の比較（目視所見）
