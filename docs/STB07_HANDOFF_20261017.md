## 目的

既存の「取得できなくても地名だけで創作できる」動作を維持しつつ、**成功した空結果と、失敗して得られなかった結果**を区別する。ユーザーの生成操作が古い地点を上書きしないSTB-01〜03のAbort処理は引き継ぐ。

## 実装範囲

- HTTP 429を `rate_limited`、タイムアウトを `timeout`、形式違反を `invalid_response` として内部分類。失敗した取得元の情報だけを最小限に記録。
- OpenPOIは二つの検索要求の**部分成功**を取りこぼさず、有効なPOIだけを使用。必要に応じてOSM/Overpassを補完取得。
- `complete / partial / empty / unavailable` の取得状態を返す。無効な分類は従来どおりポエムから除外。
- 一部成功時は「一部の施設情報を取得できませんでした」、429を含む場合はアクセス制限の旨を表示し、取得済みPOIに基づいて生成。
- 全取得失敗時は**地名のみで創作**し、再生成で再試行できる旨を表示。成功した空結果は「利用できる周辺施設データが見つかりませんでした」と表示し、「周辺に何もない」とは断言しない。
- 同じ地点・文体で再生成する際、**成功時の施設キャッシュは使い回し、通信の失敗・部分取得をキャッシュ確定しない**。429に対し即時自動再試行や大量の再リクエストは行わない。再生成は利用者の明示的操作。
- 出典・座標正規化・分類信頼度の既存仕様、広告文体、UI全体は原則変更しない。

## テストと検証ゲート

既存**23件**＋新規**6件**、計29件を予定。以下を検証する：

- 両ソース障害（429/503）→地名だけで生成、再生成で再試行
- OpenPOIの検索要求の一部が429→取得済み施設を維持
- OpenPOI障害でOSM成功→補完から生成
- 両方が成功し空結果→障害とは表示しない
- JSONスキーマ不正や500→地名フォールバック
- タイムアウトと明示キャンセルの区別

**確認済み**：GitHub Actions最終29件、PR差分、mainマージ、Pages配信、公開HTMLの配信コード。**未確認**：実ブラウザ操作・iPhone/Android実機。

1. CI結果とテストログを確認し、失敗があれば同一ブランチで修正。
2. mainにマージする場合はActionsのPagesジョブSUCCESSと公開HTML取得結果を確認。
3. 地点選択→POI取得→生成を実ブラウザ操作して検証（Opera接続不能のため現時点では未確認）。
4. 初版の生活情報表示（LIFE-00/LIFE-01）では取得状態・データ取得時刻・直線距離をUIへ再利用する。
5. 空データが「周囲に施設がない」ことの証明にならないことを維持する。
