## 3. MAPFX-01｜地図の光柱を軽量実装

### 3.1 目標となる見え方

ユーザーが選んだ一点から、金白系の細い主光柱（1本）と弱い散光（0〜2本）が地図の上方に伸びる。ゲーム風の大光線ではなく、住まい広告の静かな「位置の演出」。地図タイルの通り・地名・施設ラベルを塗りつぶさない。見えた線を現実の施設、建物、交通、道路の証拠と誤認させない。

初版パラメータ（いずれも**試験値**）：
- 主光の幅：基部 5〜10 CSS px、上側の光芒 25〜55 CSS px。縦高 120〜260 CSS px。地図サイズの35%程度を上限。
- 主光の不透明度：薄く、低彩度のシャンパン色／白、文字ラベルを必ず読めること。
- 入場フェード：350〜600msを一度だけ。常時の激しい点滅や自動パルスはしない。
- 初期表示はONでもよいが、明瞭な「光演出OFF」切替を設け、prefers-reduced-motionではアニメを停止して静止光またはOFF。
- ユーザー操作を奪う全画面オーバーレイ、別API、位置照会は導入しない。

### 3.2 実装方式の選定

**採用候補：Leaflet地図コンテナ上のSVG／HTMLオーバーレイ（CSS gradient、pointer-events:none）**。選択点の lat/lon を map.latLngToContainerPoint で画面座標へ投影し、描画位置だけを更新する。光自体は画面上方向へ伸びる創作演出であり、地理線として地図上に固定しない。タイルや attribution コントロールより手前・操作ボタンより奥で描画し、左右のクリック領域を塞がない。独立したDOM要素を追加し setPin の描画更新と同期する。

禁止する実装：地理緯度経度に見せかけた疑似経路polyline、スクリーン固定でピンだけが別位置へ移動する光、canvasで毎フレーム描画する常駐requestAnimationFrame、膨大なdrop-shadow blur、ズーム毎に重複追加されるレイヤー。

Leafletイベントは move/zoom/resize に追従し、ズーム・パン操作中にも最終的なピンと光源が一致。古い地点の非同期ジオコーディング結果から光が戻らない。Lがロード失敗したら光だけの独立表示はしない。

### 3.3 テスト・受入

- 地図選択とプリセット切替の後、光基部が新しいピン中心に一致（誤差を最大3 CSS px目標）。
- ドラッグ、ズーム、地図コンテナ幅変更で追従。イベントの重複リスナー・DOM重複無し。
- オーバーレイ pointer-events:none、操作やズーム／地図スクロールに影響なし。
- 地図タイル未読込、L未定義、API失敗でクラッシュしない。
- reduced-motion、光演出OFF、モバイルSafari（320/375/390px）で静止・無効化状態を確認。
- 国土地理院の出典や地図操作説明を隠さず、光が実際の地理現象の印象を与えない。背景画像に焼き込まない。
- CIはモックで座標変換・クリーンアップを確認。実機の透明度／視認は別ゲート。

### 3.4 最初の小PR

変更範囲：index.htmlのmap DOM／CSS／初期化とsetPin同期、Nodeテスト。追加ライブラリ不要。プレビューON/OFF切替と非対応環境のフォールバックを付ける。本番印刷PDFにはMAPFXを自動で焼き込まない（将来の地図画像出力は別審査）。

### 4.2 マニフェストの設計

ファイルは配信予定の assets/images/manifest.json とし、PNG/WEBPの実ファイル投入前に少数fixtureでスキーマを確定する。最低限：

~~~json
{
  "schemaVersion": "1.0",
  "assets": [
    {
      "id": "app003-city-night-001",
      "group": "city_night",
      "themes": ["urban", "architecture"],
      "slots": ["hero", "residence", "print_hero"],
      "orientation": "portrait",
      "renditions": {
        "screen": {"path": "assets/images/web/app003-city-night-001.webp", "width": 1200, "height": 1600},
        "print": {"path": "assets/images/print/app003-city-night-001.webp", "width": 2400, "height": 3200}
      },
      "focalPoint": {"x": 0.54, "y": 0.42},
      "kind": "generated_illustration",
      "caption": "架空建築イメージ",
      "rightsStatus": "review_required",
      "sourcePromptId": "PROMPT-CITY-01",
      "reviewStatus": "candidate"
    }
  ]
}
~~~

これは**想定JSONの形でありファイルも画像も未作成**。screen／printのpathは未生成のプレースホルダ例。実制作段階に必須の追加メタデータは出力モデル・制作日・著作権者／使用許諾／再配布可否、実体SHA256、批評メモ、サムネイル、禁止表現タグ。生成AIの利用条件に従い、他社広告の無断複製をしない。

### 4.3 配信・負荷予算（提案値）

- 初期表示は原則1枚のみ、residence用は生成結果が出て必要になったときに読み込む。100枚の画像を一括ダウンロードしない。
- screen renditionはWebPを第一候補とし、初期heroの目標サイズ250〜450KB程度。遅い回線を考慮し、HTML本体から候補すべてにpreloadを付けない。
- 画面のサムネイルだけを印刷に拡大しない。印刷用解像度はA4の実際の掲載面積／望ましいppiから算定する。
- 100枚をそのままGitHubのmainに大量一括追加しない。まず10枚、次に20〜30枚。選択済みだけを段階投入し、未採用原本は別作業領域で保管・権利確認。
- Git LFSをGitHub Pagesの静的アセットURLとして無条件に前提としない。非公開素材を公開リポジトリに移動しない。

### 4.4 自動選択とユーザー選択

- 先にThemePlanのgenreId/style/intensityを使い、許可済み群から候補を絞る。暗渠等に実在の建築・設備を特定するCGを勝手に紐付けない。
- 同じ地点・同じ生成結果では画像を安定選択する（seedはsourceId＋テーマ＋出力variant）。REGENERATE時は明示的なvariant更新に応じて変化可能。
- 固定のブランド世界観と違和感が出ないよう、ユーザーが「自動／指定画像／線画のみ」を切替可能にする。
- 画像に地理的事実を背負わせない。「架空建築イメージ」「Image Photo」のクレジットを画面と印刷両方に残す。
- manifestに対象画像がない／読み込みエラー／権利未承認 → SVGへ戻し、生成本文・コピー・印刷を止めない。
- 他社の実広告写真・ロゴや版権フォントは取り込まない。必要な権利・利用条件を個別に確認する。

### 4.5 受入

10枚のfixture＋実体画像PoCで、manifest全項目検証、破損パス0、用途ごとに画像が適合、スマホcropで主題が切れない、SVG fallback成功、出典注記あり、画像読み込み失敗がアプリ機能を止めない。印刷への転用はPRINT-03で別途検査。

## 5. PRINT-03｜実広告の紙面を組む独立レンダリングレイヤー

### 5.1 何を変えるか

現行 PRINT-02 は既存画面DOMを @media print で変更する方式で、ユーザー実機では両案とも改善が必要。**印刷用の構造をWeb操作画面から分離**し、値の同一性を保ったまま紙面の構成そのものを切替可能にする。

~~~
ThemePlan + POEM + LOCATION + AssetManifest + CreditRules
      ↓ 検証済みのPresentationData（同一の主役・データ世代）
  ┌──────────────┬─────────────┬──────────────┐
  │ editorial     │ type_poem   │ location     │
  │ 主図版＋余白   │ 文字優先    │ 地図・街      │
  └──────────────┴─────────────┴──────────────┘
      ↓ 内容高さ実測・改ページ判定（機能縮退可能）
  印刷専用DOM / CSS → ブラウザPDF (Consumer PDF)
~~~

既存のPOEM・住所・直線距離・素材出典・創作注記を別の値として再生成しない。選択地点が変わった瞬間に旧版印刷を不可にするCOPY-LOCKの世代IDを共用。実在物件の価格は自動で作らない。

### 5.2 紙面テンプレートの初期候補

1. editorial：上に架空建築の図版、中央に主コピー／詩、下に主役施設と小さな裏付け。主図版なしの場合でも線画で成立。
2. type_poem：大きな和文・欧文見出し、余白、補助グラフィック。暗渠・ポスト・側溝など都市インフラの過剰広告との相性を検証。
3. location：小さな位置模式図と主役1＋補助2、場所の個性を強く語る詩をサイドに置く。実測ルートのない徒歩表記は禁止。

現行の compact／onepage は移行期間の比較対象として保持。いきなり削除しない。

### 5.3 自動組版の安全境界

初版はA4縦を前提にし、印刷対象はポエムだけ、LOCATION0/1/3件、通常名・長名／長住所100字以上、画像あり／画像なしの固定セット。

文字を自動で削る「1ページ保証」はしない。ブロックの実寸を印刷準備DOM（可視域外で測定してから破棄、レイアウトを潰さない）で計り、標準→余白調整→2列化→使用許諾済み画像縮小の順で試し、一定の字級・注記サイズ以下にはしない。収まらなければ2ページレイアウトへ安全に移り、ページ数を事前またはプレビューで明示する。ブラウザの印刷挙動・Safariとの差をQAで記録する。

出典と創作注記は紙面内必須。不要な「料金・学区・眺望保証」は埋めない。Webからのスクリーンショットを印刷の正本にはしない。

### 5.4 受入ゲート

- H-01〜H-08（[品質規格](AD_QUALITY_GATES_V1_20261019.md)）の重大条件違反0。
- 神保町、京都、住宅街、POIゼロ、長い施設名、住所100字、Webフォント不通の代表7ケースでPDFの文字・出典・注記欠落0。
- POEM・LOCATION第1件・THE EVIDENCEが同じ主役。選択中や生成中は印刷不可。
- デザイン品質C/H/T/V/E/Pの採点（目標85/100は内部暫定、実企業基準ではない）を、見た目レビューで実測。
- CI fixture、Pages配信、iPhone Safari印刷プレビューを別々に証跡化。PDF/X適合・CMYKプリフライトは未対応であり、実装済と主張しない。
