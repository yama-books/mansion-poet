## 1. 検証レベル

| レベル | 目的 | 試験方法 | 実施契機 |
| --- | --- | --- | --- |
| L0 | コード構文・静的仕様 | \`node --check\`、HTML妥当性、依存の設定点検 | すべてのコードPR |
| L1 | ロジックの再現性 | Node \`node --test\`、fixture / fetchモック | データと生成ロジックの各PR |
| L2 | ページ内操作 | headlessブラウザ（必要になったらPlaywright）、固定データで検証 | UI・状態管理・リリース前 |
| L3 | 公開実ブラウザ | GitHub Pagesで検索・生成・コピー・出典の確認 | リリース候補 |
| L4 | 実機 | iPhone Safari、Android Chrome、Windows Chrome/Edge | v0.2以降、各マイルストーン |
| L5 | 手動文芸・地理審査 | 代表地点・文体・濃度によるブラインド比較と事実チェック | v0.3以降 |

**原則：** テストを実行した環境と、確認できた範囲を分けて記録する。「GitHub Actions成功」＝「スマホで動作確認済」ではない。

## 3. 必須回帰試験

### 地点の一貫性

| ID | テスト操作 | 合格条件 |
| --- | --- | --- |
| LOC-T01 | 地名検索→候補選択→生成 | 入力欄、マーカー、根拠の地点が一致 |
| LOC-T02 | 検索を続けざまに2回実行 | 新しい検索の候補だけ反映 |
| LOC-T03 | 検索中にサンプル地点を選ぶ | 遅い検索応答で地点が上書きされない |
| LOC-T04 | 地図上の離れた2点を素早くクリック | 新しく選んだ地点が最後に残る |
| LOC-T05 | 施設取得中に別地点へ移動 | 古い施設が新しい地名の作品に混入しない |
| LOC-T06 | 地名を入力し候補を選ばず生成 | 古い地点で勝手に生成しない、修正可能な案内 |
| LOC-T07 | 同じ地点、文体を変えて再生成 | 文体に応じて主題と施設順位が更新 |
| LOC-T08 | コーディネート（lat/lon）の逆転 | 明らかな不正座標を拒否 |
| LOC-T09 | 海上や対象国外を選択 | 存在しない地域属性・施設を創作しない |

### 取得とデータ

| ID | ケース | 合格条件 |
| --- | --- | --- |
| API-T01 | 正常JSON、施設あり | 地点に合うPOIを選別、出典表示 |
| API-T02 | 施設0件 | 地名ベース生成 + 「情報未取得」等の正しい表示 |
| API-T03 | 400 / 429 / 500 / timeout | 異常を区別。無限リトライしない |
| API-T04 | APIネットワーク遮断・CORS風失敗 | 地名生成に降格、画面操作は継続 |
| API-T05 | OpenPOI成功、Overpass失敗 | 有効なOpenPOIだけで生成 |
| API-T06 | OpenPOI失敗、Overpass成功 | 有効なOSMだけで生成 |
| API-T07 | 施設名同一で座標異なる | 過剰統合せず、実施設を扱う |
| API-T08 | 遠方に誤付与された座標 | 直線距離で外れたものを排除 |
| API-T09 | 住所が東京以外なのに東京駅座標 | 地名・都道府県不一致を検知し要確認扱い |
| API-T10 | 「お酒の美術館」等、名称に特殊語 | 名前だけで歴史・博物館として採用しない |
| API-T11 | category unknown / 空name / invalid lat | 保守的な分類、クラッシュなし |
| API-T12 | 出典に複数ライセンス | メタデータを落とさず保持 |
| API-T13 | 限度200近い混雑地区 | 多数店舗だけで主題が埋まらない |
| API-T14 | 範囲外完全一致が混入 | API応答を鵜呑みにせず距離再検査 |

### ポエム・コピー

| ID | ケース | 合格条件 |
| --- | --- | --- |
| POEM-T01 | 同seed／同Evidence | 同じ作品を復元 |
| POEM-T02 | 同一点で連続5案 | 3案以上で明確な主題・見出し差 |
| POEM-T03 | 濃度0 / 50 / 100 | 誇張度の差はあるが事実の真偽は変わらない |
| POEM-T04 | Heritage / Metropolis / Sanctuary | 視点と語彙が変わり、本文が不自然にならない |
| POEM-T05 | 該当するEvidenceなし | 地名のみの安全な作品 |
| POEM-T06 | あいまいな史跡名 | 裏付けのない年数や由緒を断定しない |
| POEM-T07 | 特徴語の大量重複 | 異様な「至高」「叡智」連打を抑制 |
| POEM-T08 | 長い地名、全角・絵文字・記号 | 空文字や文字列破損がない |
| POEM-T09 | 長い固有名詞 | 独自のUIで見切れない |
| POEM-T10 | 外部POI名にHTML文字列 | HTMLを実行せず、文字列で表示 |
| POEM-T11 | コピー | 見出し・本文・架空物件注記が揃う |
| POEM-T12 | 出典説明 | 生成に用いた主題の根拠と素材が一致 |

## 4. UI状態テスト

- 通信中のスケルトン/ローディング、完了、部分成功、サービス停止、検索0件、検索候補、確定済み地点。
- 320, 375, 390, 430, 768, 1024, 1440 CSS pxで横スクロールが不要。
- PCのタブ・Enter・Esc、スマホのソフトウェアキーボード。
- コントラスト、フォーカス、タップターゲット、文字拡大200%、reduced-motion。
- 地図CDN不通時も検索・生成の代替導線がある。
- 日本語Webフォント未読込のフォールバック。
- 印刷・PNG画像書き出し（実装後）で文字切れ、施設出典リンク表示の欠落なし。
- ブラウザ履歴・リロード後の破損なし（永続化は仕様に従う）。

## 5. 自動テストの導入手順

### 第1段階（v0.1.2）

1. まず現行コードのPOI処理・生成処理を「副作用のない関数」に分離する。
2. fixture JSONを用意。場所に紐づくメタデータは匿名のサンプルを中心に、公開APIの代表JSONは必要最小限・出典付き・保存ライセンス確認済みのみ置く。
3. \`node --test\` で距離・優先度・非同期選択・出典・再生成を検証。
4. 全体のJS構文と公開先のindex参照を検証。
5. CIを軽量化：OSはLinux、依存最小、npm install必須にしない選択肢を優先。
6. CI成功後にPagesデプロイを実行するようworkflowを調整。

### 第2段階（v0.2以降）

PlaywrightなどのE2Eは必要な主要ルートだけ導入。ブラウザインストールコストとCI課金・実行時間を監視する。重いブラウザテストをすべてのpushで繰り返さなくてよい。GitHub-hostedと自宅self-hosted runnerの使用はリポジトリの性質・負荷・セキュリティを見て決める。

外部サービスへの実APIテストは公開確認時に**限定的**に行う。CIの高頻度大量アクセスは禁止。fixtureを使った再現性を優先。

## 6. 品質スコアカード

数値は**これからの受入基準（目標）**で、実測成果ではない。

| 指標 | 初期の合格基準 | 計測 |
| --- | --- | --- |
| P0 / 重大障害 | 0件 | issue / リリースレビュー |
| 核心フロー | 代表地点16/16で、施設ありまたは地名フォールバックで生成可能 | 固定テスト |
| 固有の土地らしさ | 取得できた地点のうち85%以上で、主題とEvidenceの対応を説明できる | 手動レビュー |
| 文章の変化 | 同地点5案で異なる主題/見出しが3案以上 | fixtureテスト |
| 未確認の固有事実 | 審査済みセットで重大な捏造0件 | 地理・文章レビュー |
| 操作性 | 場所確定→生成→コピーを説明なしで完遂 | 実機テスト |
| 出典 | POIを用いた作品で取得元と範囲の表示率100% | UIテスト |
| モバイル | 320px幅でも主要操作が妨げられない | 幅テスト |
| アクセシビリティ | 主要文字4.5:1、キーボードで主要フロー、reduced-motion | 測定 / 手動 |
| 性能 | 初期画面の主領域描画が遅くならない。API待ちを視覚的に示す | 現行版との比較測定 |
| 公開 | CI成功→Pages配信→HTTP 200→表示・生成確認 | Actions / 実ブラウザ |

**性能目安（性能予算として採用前に現行実測を取得）**：本体CSS/JS（地図タイル・Webフォント除く）は初期転送で極力小さく保つ。3G/4G・スマホ等の条件を固定してLCPや操作遅延を測定。固定の数値目標は基準値を測ってから最終確定。

## 8. リリース前の定型ゲート

1. mainに入れるコードはテスト成功・レビュー完了。
2. Pagesの公開ビルドが成功。
3. 公開URLから操作実証（代表地点：地名検索、プリセット、地図、生成、再生成、コピー）。
4. 公開APIの成功・不成功の両経路を確認。
5. iPhone等の対象ブラウザの試験結果を記録（未検証なら明示して正式版へ進めない）。
6. 生成した作品で、具体的な施設の存在と創作の誇張が混同されていない。
7. コピー・画像・印刷に架空物件の注記が残る。
8. 出典、ライセンス、プライバシー説明を再確認。
9. changelogとROADMAPを更新し、リリースタグを付与。
10. 問題があれば前版の正常commitへ戻せる。

## 9. 現時点の実績

2026-10-17時点で確認済み：
- GitHub Pagesで \`index.html\` 公開、HTTP 200。

- iPhone SafariやAndroid Chromeの実機操作。

- Overpass障害時の全経路。
- 代表地点の網羅的な評価。
- 新しい生成方式や広告画像の品質。
