## 実装・検証の境界

1. `SubjectPolicy.decideSubject(p)` は原データを変更せず、`allow/context_only/suppress/needs_review`、safeAngles、forbiddenClaims、理由、出典IDを返す。name-only / source theme conflictを主題へ昇格しない。
2. `choosePOIs` の入口と `LocationHighlights.create` の入口にallow判定を加える。THE EVIDENCEは選定後のPOIから描画しているため、除外施設の名前が逆流しない構成。
3. LIFE-01は元POI集合から独立に生成しており、文芸向けの非採用が生活施設情報の消去にはならない。
4. `forbiddenClaims` は禁則の契約であって、現時点のコピー全文を機械的に検査・書換えする実装ではない。別セッションのPOEM-01文言は本PRで変更しない。
5. PS-01〜28の仕様例をそれぞれユニットテストで確認し、表示経路と競合分類を限定的にテスト。実OpenPOI/OSM・公開ブラウザ・スマホ実機の受入を混同しない。
6. GEO-00で郵便ポスト・側溝・暗渠の取得実例、タグ分布、匿名地物、線形距離、API制限を少数回の読み取りで調べてからGEO-01へ進む。まだ外部POI APIへの大量アクセスは一切実施していない。
