# 地理・施設データの取得方針

更新日：2026-10-16

## 目的

ユーザーが選んだ全国の地点の周辺情報を取得し、創作コピーの主題として活用する。データをそのまま広告上の事実主張に転用せず、**参照された根拠と創作的な形容を分ける**。

## v0.1で利用する外部リソース

| 目的 | データ・サービス | 現状 |
| --- | --- | --- |
| 地名・住所検索 | 国土地理院 地名・住所検索 API | 実装済、通信環境依存 |
| 座標から地名取得 | 国土地理院 逆ジオコーディング | 実装済、通信環境依存 |
| 地図表示 | 国土地理院 淡色地図タイル | 実装済、通信環境依存 |
| 地図描画 | Leaflet 1.9.4（CDN） | 実装済、通信環境依存 |
| 近傍の施設 | OpenStreetMap / Overpass API | 約850m範囲の一部カテゴリーのみ試験的取得 |
| 詩的コピー生成 | ブラウザ内の辞書・テンプレート | 実装済、外部生成AIを使用しない |

## 追加候補

1. **国土数値情報：** 土地利用、鉄道、公共施設などの全国オープンデータ（データセットごとにライセンス確認）。
2. **国土地理院：** 標高、地形分類、地名の成り立ちを補う情報。
3. **不動産情報ライブラリ：** 都市計画、施設関連の情報（利用資格・APIキー・規約確認が前提）。
4. **文化庁・自治体オープンデータ：** 指定文化財、歴史資源、地域文化。
5. **地名辞書・地域誌：** 信頼できる公開資料からの地名由来や歴史の補完。

## データの扱い

- APIの施設名や属性は**取得できた範囲内の情報**として表示し、網羅性を主張しない。
- 施設の現在の営業状況、アクセス時間、景観や騒音などの推定は、確認可能なソースがない限り出力しない。
- 周辺施設と「徒歩○分」「眺望に臨む」「日常の静謐」の間に論理の飛躍がないか検査する。
- 地名・座標から作った生成文の出典表示には、取得元・取得時刻・距離・対象カテゴリーを段階的に追加する。
- 地点選択情報はv0.1では基本的にブラウザで処理するが、地名検索・地図タイル・周辺施設取得時には検索語または座標などが外部サービスへ送信される。第三者送信を画面や利用説明で明らかにする。
- OSMの帰属表示を維持する。第三者の写真や文書を安易に取り込まない。
- 外部APIの障害時は「未取得」を明示し、架空の施設名を補完しない。

## 次回の技術課題

- オーバーパス取得結果に緯度経度／中心点と直線距離を持たせる。
- POI分類を拡充し、重複と施設の偏りを除去する。
- 参照地点と取得地点のズレ、検索タイムアウト、リクエスト競合をテストする。
- データ取得と文章生成の処理を分離し、将来のソース追加を容易にする。
- エラー種別と出典情報をUIに表示し、取得できた情報と創作文の区別を改善する。
