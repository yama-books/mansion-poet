# 地理・施設データの取得方針

更新日：2026-10-16

## 目的

ユーザーが選んだ全国の地点の周辺情報を取得し、創作コピーの主題として活用する。データをそのまま広告上の事実主張に転用せず、**参照された根拠と創作的な形容を分ける**。

## OpenPOI連携仕様（2026-10-16）

- 接続先：`GET https://api.openpoiapi.com/v1/search`
- キー／登録：不要。CORS `Access-Control-Allow-Origin: *`。
- 地点：`center=経度,緯度`（**lat,lonの順ではない**）。
- 半径：`radius=850`（メートル）。
- 無条件近傍：`limit=180`。加えて `q=図書館 美術館 博物館 公園 大学 神社 寺 書店 駅 劇場`、`limit=100` を併用してテーマ性のある施設を補完。OpenPOIの `q` は空白で区切った語のOR検索。
- 応答：`results[]` の `name`、`category`、`business_type`、`lat`、`lng`、`licenses`、`attributions` を読み取る。
- 選別：名前・カテゴリーから文教／文化／緑／歴史／交通／商業／飲食等に分類し、中心との直線距離が850mを超える施設は除く。テーマごと最大2件、全体で最大12件を採用。
- 補完：特徴データが少ないとき、緑地カテゴリが見つからないとき、自然文体のときはOpenStreetMap／Overpassへフォールバックまたは追加取得する。
- 通信障害：OpenPOIが失敗した場合はOverpass、両方失敗した場合は地名のみで生成。
- 出典：UIに「OpenPOI API」のライセンス・出典ページへのリンクを配置。個々の施設についても「OpenPOI」「OSM」を表示。
- 保存：現在は利用セッションのメモリ上で直前の取得結果を再生成に使うのみ。DB等への永続保存は未実装。

**制約：** OpenPOIの `category` が不明な施設は多く、施設名による分類には限界がある。半径絞り込みと距離検証は、誤座標を完全に除去する保証ではない。ソースによっては閉業施設も残る。取得できた施設は網羅的なリストとは限らない。

公式FAQではAPI全体の定常200リクエスト/秒・バースト600リクエスト/秒を超えると429となる。接続できない場合も多重再試行は行わない。

**実行検証：** JavaScript構文チェックとモック入力の分類・距離除外・座標順・失敗時フォールバックテストを実施。2026-10-16にOpenPOI APIの `GET /v1/search` を神保町座標でHTTP 200応答・有効JSON・施設名・座標を実際に取得できることを確認（半径850mの無条件検索・特徴語検索）。**GitHub Pagesなど実ブラウザからのCORS・画面操作確認は未実施。**

## 追加候補

1. **国土数値情報：** 土地利用、鉄道、公共施設などの全国オープンデータ（データセットごとにライセンス確認）。
2. **国土地理院：** 標高、地形分類、地名の成り立ちを補う情報。
3. **不動産情報ライブラリ：** 都市計画、施設関連の情報（利用資格・APIキー・規約確認が前提）。
4. **文化庁・自治体オープンデータ：** 指定文化財、歴史資源、地域文化。
5. **地名辞書・地域誌：** 信頼できる公開資料からの地名由来や歴史の補完。

## データの扱い

- APIの施設名や属性は**取得できた範囲内の情報**として表示し、網羅性を主張しない。
- 施設の現在の営業状況、アクセス時間、景観や騒音などの推定は、確認可能なソースがない限り出力しない。
- 周辺施設と「徒歩○分」「眺望に臨む」「日常の静謐」の間に論理の飛躍がないか検査する。
- 地名・座標から作った生成文の出典表示には、取得元・取得時刻・距離・対象カテゴリーを段階的に追加する。
- 地点選択情報はv0.1では基本的にブラウザで処理するが、地名検索・地図タイル・周辺施設取得時には検索語または座標などが外部サービスへ送信される。第三者送信を画面や利用説明で明らかにする。
- OpenPOIの画面出典リンクを維持する。ライセンスの義務が再配布や加工に及ぶ場合は内容を確認する。OSMの帰属表示も維持する。第三者の写真や文書を安易に取り込まない。
- 外部APIの障害時は「未取得」を明示し、架空の施設名を補完しない。

## 次回の技術課題

- オーバーパス取得結果にも緯度経度／中心点と直線距離を持たせて検証する（現在はOpenPOIのみ距離検証）。
- POI分類を拡充し、重複と施設の偏りを除去する。
- 参照地点と取得地点のズレ、検索タイムアウト、リクエスト競合をテストする。
- データ取得と文章生成の処理を分離し、将来のソース追加を容易にする。
- エラー種別と出典情報をUIに表示し、取得できた情報と創作文の区別を改善する。
