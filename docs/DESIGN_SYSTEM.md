# POÈME / ESTATE デザインシステム・UI実装仕様

更新日：2026-10-17  
状態：**提案仕様（現行UIへの未実装変更を含む）**  
関連：[開発マスタープラン](DEVELOPMENT_PLAN.md)

## 1. デザイン原則

**「何のためか分からないほど、美しい高級マンション公式サイト」**。

ただしギャグ的な外観にはしない。独特のおかしみはコピーの大げささに任せ、UIは礼節ある高級住宅広告の顔を保つ。

1. **建築的**：グリッド、余白、極細線、端正な垂直・水平を優先。
2. **品のある暗さ**：深緑とチャコールを基調とし、生成作品の画面を最も深いトーンにする。
3. **長い呼吸**：見出しの改行・文字間・行間・余白で演出。アニメーションは補助。
4. **明快な機能**：検索、確定地点、生成、コピーは迷わせない。作品のために操作を犠牲にしない。
5. **奇抜さは文中に**：装飾アイコン・擬似的な高級感・ゴールドの乱用を避ける。
6. **動きの統一**：0～2方向のスライド、短いフェード、線の伸長に限定する。

## 3. 情報設計

### ページの4節

**A. HERO / Invitation**

大きな欧文タイトル + 「その街に、まだない物語を。」。右に独自建築SVG。主要操作へのリンクは最初の画面ですぐに理解できる位置に置く。

**B. LOCATION / Discovery**

左：地名入力・検索候補・サンプル地点・文体・濃度・生成CTA。右：地図。モバイルは1カラムで、検索と生成CTAを先、地図はその後。

**C. THE RESIDENCE / Result**

見出し、本文、架空物件名、建築ビジュアル、コピー・再生成・印刷。生成の結果が視覚的な主役。データ取得中は骨格線や控えめな進行表示を出し、実際に完了するまで成果を装わない。

**D. THE EVIDENCE / Provenance**

採用した地域特徴、施設情報、出典、範囲、取得不能事項、創作注記。作品の世界観を壊さず、見ようと思えば根拠が辿れる。

### 進行状態

\`\`\`text
初期状態
  → 入力中（選択確定ではない）
  → 候補一覧 or 地図指定
  → 地点確定
  → 施設取得中
  → 生成成功／情報不足でも生成／失敗
  → 再生成・コピー・印刷／画像出力
\`\`\`

**最優先のUX不具合**：地名を入力しただけなのに古い地点のポエムが作られる状態をなくす。入力欄と選択済み地点を別物として扱い、検索・地図選択のステータスを表示。

## 4. 操作仕様

### 地名検索

- Enterと「検索」ボタンの両方で実行。
- 読み込み中は検索ボタンのラベルと状態を反映。
- 候補の各行をフルタップできるサイズにし、選択地点の住所／座標を確定。
- 古い候補の応答は新しい検索と混ぜない。
- キーボードで候補を上下選択、Enterで確定、Escで閉じる（導入検討）。
- 検索結果なし／検索サービス停止は別メッセージにする。

### 地図

- マーカーが現在選択地点と一致すること。
- 外部逆ジオコーディング応答が遅れたら、古い地点に戻さない。
- 地図が描画不能でも地名検索／プリセット／生成は使える。
- ピン／地図の操作説明は短く、暗すぎず可読。
- 出典表示は地図の上または下から確認可能。
- 地図は主要操作を遮る位置に固定しない。

### 文体

3つの文体カードは今のまま基本方針を守る。各文体に1行の説明を付けてもよいが、初期画面を肥大化させない。選択状態は**枠線 + 塗り + アクセシブルな押下状態**で分かること。

### 濃度スライダー

0〜100は維持。現在値を即時表示。最低限「端正」「王道」「超越」の目安ラベルを補助的に示す。値を動かすだけで生成済み作品を書き換えない。再生成で反映。

### 生成ボタン

- 有効／待機／生成中／完了／部分成功／通信不可を区別。
- 非同期処理中でも「新しい地点を選んだら何が起こるか」を明確にする。
- 一時的な失敗は地名ベース生成に切り替え、文章の完成を優先。
- エラーを静かに握りつぶして、すべて「施設0件」と誤表示しない。

### 作品アクション

コピー：成功／失敗を明示（2秒程度で戻してよい）。印刷：文字切れ防止。再生成：前回案との違いを出す。画像出力：追加時に外部画像の著作権に注意。

## 5. モーション仕様

| 動作 | 提案 | 条件 |
| --- | --- | --- |
| ヒーロー見出し | opacity + translateY(10〜16px)、450〜650ms | ページ初回表示 |
| セクション見出し | opacity + translateY(8〜12px)、320〜480ms | 初回表示／再進入は基本発火しない |
| 結果見出し | opacity + translateY(10px)、380〜520ms | 生成成功後のみ |
| 右側の建築パネル | 右から translateX(12〜20px)、400〜650ms | 無駄な大振り移動は禁止 |
| 根拠タグ | 30〜70msずつ時間差、小さなフェード | 証拠が実際に揃っている場合 |
| ボタン hover | 180〜240ms、背景色や罫線の変化のみ | hover対応端末 |
| 入力補助 | 150〜250ms。必要以上に揺らさない | 結果候補や状態表示 |

- \`prefers-reduced-motion: reduce\` のときは原則transition/animationをオフ。
- セクションの位置やレイアウトを押し出す動きは避け、transform/opacity中心。
- メニューなどの操作に初回アニメを強制しない。
- 画面右から列ごとに入る演出を使うなら**広い画面の短いデモンストレーションだけ**。生成結果や入力候補を意味なく遅らせない。
- モーション参考（採用例は個別検証）：https://motion-reference.takayustudio.jp/

## 6. モバイルの表示戦略

優先確認幅：320、375、390、430、768px。横向きも想定。

- 狭い画面では巨大な建築画像を圧縮し、主操作への導線を高い位置に置く。
- 操作カードは端に詰めすぎず、誤タップしない余白を確保。タップ領域は目安44×44 CSS px。
- 入力フォント16px以上。
- 地図は縦に大きく取り過ぎない（例えば360〜420pxを試験）。
- 生成作品は最初に見出し・本文、その次にアート画像を表示。
- fixed / stickyによる画面占有は必要な場合のみ。
- 右端の重要文字や余白がsafe-areaに干渉しない。
- 作品の改行はモバイルで再計算し、PC用改行を強制しない。

## 7. アクセシビリティ

- 色だけに依存せず、選択状態・エラーを文字でも表現。
- フォーカスの視認性確保、論理的なTab順。
- 入力にlabel、検索結果に適切なライブ通知、ボタンに状態。
- 地図なしで全機能の主要フローを完結可能にする。
- 装飾SVGを \`aria-hidden=true\` にする。
- 通常文字の色コントラスト目標4.5:1以上、巨大文字3:1以上。
- 文字サイズを200%まで拡大しても主要内容が切れない。
- 長いアニメーション・強いパララックス・自動動画を採用しない。

## 8. UIレビューの承認条件

各UI変更PRには、最低限次を添付する。
- PC 1440px、モバイル 375px、狭い画面320px の before / after。
- 地名入力、候補選択、API取得中、成功、障害、コピー成功の状態を確認。
- 作品見出しが改行と共に意図どおりに読める。
- データの注記と出典リンクが保持される。
- ユーザーが3操作程度で「土地を選択→生成」の中核体験へ到達できる。
- 既存の広告世界観を維持。派手なカラーや過剰なカードUIにならない。
