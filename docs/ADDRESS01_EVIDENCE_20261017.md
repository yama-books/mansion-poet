# ADDRESS-01｜施設所在地の出所と粒度を区別する

2026-10-17 JST / APP-003 / POÈME / ESTATE

## 目的と範囲

前段のGEO-02は小さな施設の選択式検索まで、SELECT-01はポエムと広告先頭カードの同一根拠まで実装・CI完了。今回のADDRESS-01は**施設個別の所在地がなければ未収録とする**原則を明確にして、公開広告の誤解を減らす小規模変更。既存のPOEM-01の630短文、LOCATION-01の117組の広告コピー、SAFE判定、外部APIの呼出し回数は変更しない。

## データ契約

`LocationHighlights.addressEvidenceFor(p)` は `{text, precision, source}` を返す。

- `reported`：提供元の個別POIレコードの `address` 文字列、またはOSMの当該要素の `addr:full`。現地の実測・郵便住所の完全性の**保証ではない**。
- `street`：OSM `addr:street` + `addr:housenumber`。都道府県、市区町村等のタグは元データにある場合のみ連結。欠けているものを補わない。
- `area`：OSMの地域・市区町村等のタグ、またはOpenPOI自身の `recordPrefecture` / `recordCity`。これを番地付き施設住所として表示しない。
- `unknown`：いずれも欠落。所在地は「公開データ未収録」と表示し、選択地点の住所を流用しない。

結果のカードには `address`, `addressPrecision`, `addressSource` を付与。利用者向けラベルは「所在地（公開データ）」「所在地（公開データの街路情報）」「所在地（地域情報のみ）」「所在地詳細：公開データ未収録」で明示。

このPRは**POI専用逆ジオコーディングをまだ導入しない**。同名地物の住所を別地物へ転記しない。OSMの構造化住所タグが実際に提供されること自体はAPI依存で未検証。誤植した元ソースの住所を自動で訂正できるとも主張しない。

## 代表テスト

1. 施設固有のOpenPOI/OSM full addressと、街路タグ群を区別
2. area-onlyとmissingの区別
3. 選択地点の名称・住所が他のPOIカードに流用されない
4. 場所の市区町村のみが分かる場合、「地域情報のみ」として出る
