## 1. 選定理由と検証範囲

「強いマンションポエムだけを収集してしまう」という偏りを補正するため、生活利便や購入検討材料の説明を重視する広告を候補に選んだ。今回はこれまで不足していた栃木、福井、鹿児島の3地域と複数事業者を含めた。

- **8ページ**は公開サイト取得でHTTP 200と主要な文章を確認。
- **S20のTOP**は取得ツールでタイムアウト。別の公開Webページ閲覧で本文を確認。明示的なHTTP応答番号は取得していないため200とは記録しない。
- **S20の誤ったURL** \`/sakuradori-jumonji/index.html\` が404を返すことを確認し、URL台帳には含めない。正本URLは末尾スラッシュの \`/sakuradori-jumonji/\`。
- 広告の「徒歩○分」、現存施設名、通学指定校、診療科目や開発計画を研究者が第三者検証したわけではない。あくまで広告の**書き方・情報設計を分析**している。
- 画像・アニメーション・スマホ画面は直接評価していないため、V（視覚）は全件 N/A とする。

## 3. S20：アルファステイツ桜通り十文字（栃木・宇都宮）

公式：[TOP](https://www.anabuki-style.com/sakuradori-jumonji/)／[CONCEPT](https://www.anabuki-style.com/sakuradori-jumonji/concept)／[LOCATION](https://www.anabuki-style.com/sakuradori-jumonji/location)

**TOP**：日常の移動の軽やかさを主題とし、駐車場率・物件の間取り・価格など検討者向け情報を早い段階で表示。宇都宮LRTの西側延伸に関し、広告に「2036年3月開業予定」と記載された新停留所を紹介している。

**CONCEPT**：学校群が集まる文教地区と、家族が快適に暮らすという価値を結びつける。ポエムは極端に抽象的ではなく、学校・住戸設計・設備などの説明によって根拠を補っている。

**LOCATION**：教育施設（複数学校）、公園・文化（県立美術館等）、日用品（スーパー、百貨店）、商店街を分けて提示する。

**アプリへの教訓**：
- 駐車場比率・実住戸面積などは**その物件の販売情報**であって、任意地点の架空物件を生成する材料には使えない。
- 将来計画のLRT停留所は、現時点で利用可能な駅や停留所リストに追加しない。公共機関の正式発表・時点・計画変更可能性は別途確認が必要。
- 文教エリアであっても、学校を選べるかどうか、通学先として指定されているかを自動推定しない。

## 4. S21：ポレスター福井駅東ブライティア（福井）

公式：[TOP](https://polestar-m.jp/1026/)／[DESIGN](https://polestar-m.jp/1026/design)／[LOCATION](https://polestar-m.jp/1026/location)

**TOP**：福井駅東口の交通・市街機能、買物など便利さの訴求と、住宅地の落ち着き・個人の時間という詩的な対比。

**DESIGN**：雪の多い地域の生活に対応する駐車場の融雪設備やタイヤ置場、エントランスの材質と陰影、住戸のプライバシー性が具体的に記載されている。これらは**現実の物件固有の設計設備**であり、地理情報から自動生成できるわけではない。

**LOCATION**：福井駅、商業・公共・文化を兼ねる「アオッサ」、別の商業施設「ハピリン」などを、複合施設とその建物内部の用途・階数で説明する。例えばアオッサの一つの建物に商業フロア、市立図書館、ホールがあると広告が記す。

**アプリへの教訓**：
- 「施設1件＝機能1種」ではない。**施設の建物（container）と、内部の図書館・店舗・ホール（tenant/service）**は親子関係として扱える可能性がある。
- 一棟に機能が複数あるからといって、無条件に生活施設が3〜4件「近い」と水増ししない。まずは用途別に参照可能な機能を見せ、施設数を重複集計しない方針を検討。
- 閉店、時刻、曜日、施設の利用対象は広告だけでは最新性を担保できない。

## 5. S22：エイル上荒田の杜（鹿児島）

公式：[TOP](https://eir.co.jp/uearata/)／[CONCEPT](https://eir.co.jp/uearata/concept.html)／[LOCATION](https://eir.co.jp/uearata/location.html)

**TOP**：鹿児島中央駅・市電・病院・スーパー・学校などを定量的に見せる。広告の具体的な買物・交通情報を軸に、洗練した住まいの世界観を併置する。

**CONCEPT**：都市の光、緑、住まいの落ち着きという対比と、格式を表す短い言い切りを併用する。

**LOCATION**：上荒田の杜公園、鹿児島市立病院、複数スーパーなどの施設名と広告掲載距離を示す。さらに「2028年までの市立病院再整備計画」という将来の増築・改修を紹介する記述がある。

**アプリへの教訓**：
- **既存の病院**と**将来予定される増築・改修**は異なる。未来の増床・サービスが現時点で利用できると誤表示しない。
- 広告に「病院徒歩○分」と書いてあっても、診療可否や利用条件は別情報。アプリでは店舗／施設の存在と機能の最新確認を分ける。
- 複数の食品店が同じ徒歩圏でも、品揃え・営業時間はAPIデータなしに推定しない。

## 6. 既存の生成エンジン／REALITYへ加える研究上の論点

| 論点 | 運用案 | 対応する既存仕様 |
| --- | --- | --- |
| 発表済み交通事業と供用中の交通施設の区別 | PLANNEDは実際の交通アクセスへ混入させず、根拠が取れる場合のみ別表示 | LIFE-D03 |
| 複合施設1件に複数の生活用途 | 親の建物IDと内部テナント／サービスを整理し、利用可能性と出典をそれぞれ保持 | LIFE-D07のPOI種別補強 |
| 地域の雪・気候への建物側の対応 | 購入対象の建物設備と地域の一般環境情報を厳密に分離する | LIFE-D09 |
| 病院が営業中でも増築・新サービスは予定 | 施設単位と事業計画単位の状態・時点を別に管理 | LIFE-D03/D10 |
| 住宅広告の目的別構成 | DREAMの詩からREALITYの買物／交通／医療などへ自然に遷移 | LIFE-D08 |

この回では**コードの変更や施設DBの実装は行わない**。
