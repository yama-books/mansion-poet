## 1. 結論

今回の高品質コンセプト画像を大量に所蔵する計画は維持する。ただし、画像を**完成広告のままアプリの動的広告として掲出する方式は採用しない**。生成モデルで写真・レイアウト・文字・地図を一体のPNGにした場合、建物画像の上に描かれた文字の非破壊除去、任意の文字への置換、架空地図の実座標への差替え、高解像度A4出力、POEM/LOCATIONの一致保証ができない。

**採用する最終構造：**
1. **REF（完成広告の見本）**：完成度・画風・余白・視線誘導を評価するための1枚。文字入りでもよい。ただし閲覧資料であり、内容・場所・徒歩分・販売価格を事実として転用しない。
2. **RECIPE（再現可能な構図）**：大見出しの幅、写真枠、写真のトリミング位置、可読性・情報量と見出しの改行・地図の配置など、数値化して再組版できる規則。Markdownと機械可読JSONに保持する。必要ならHTML/CSSによる独立モック。
3. **ART（独立した画像素材）**：一場面・一ファイル、文字・数字・価格・住所・地図・ロゴ・カード・枠線を含まない。写真／イラストだけを独立生成し、原画と用途別変換版を保存する。使用権・採用・印刷適合は別途審査する。
4. **RENDER（実際の広告）**：既存PRINT03のPresentationData（同一生成トークンのPOEM＋LOCATION＋距離・出典）をRECIPEのHTML/CSS/SVGへ流し込み、承認済みARTだけをレイヤーとして重ねる。図版がない/壊れた/低ppiなら既存SVGフォールバック。地図は実座標と適法なタイル／位置図で組み立てる。

REF保存、RECIPE策定、ART候補生成、公開用素材許諾、PRINT03統合、Web配信は**別々の状態**で管理する。「完成広告画像を出した」だけで「実装素材が完成」とはしない。

## 2. 今回の6点をどう使うか

| REF | 視覚的価値 | そのまま実装しない理由 | 独立ARTとして新規制作する主題 |
|---|---|---|---|
| 0003 書店・文教 | 本棚の奥行き、暖色照明、知性の情緒、写真と詩の対比 | コピー・模式地図・架空販売情報が混在。768×1024原画は印刷全判にも小さい | 架空の書棚空間、無文字の読書風景、街角ペンスケッチを**別ファイル**にする |
| 0004 公園・緑地 | 葉の透過光、池・並木・季節で変化する色、明暗の階層 | 季節違いの複数景色、見出し・距離・地図が一体。768×1024のA4全判は低ppi | 木立の歩道、緑地の遠景、季節差のある公園一般情景を**単一シーンずつ** |
| 0005 川・暗渠 | 水脈と地層を連想させる水彩、概念図を誌面と結ぶ造形 | 架空の模式図は地理的な真実ではない。暗渠を実際に開水路と誤認させうる | 地中の水脈を暗示する**抽象的水彩**／現地と無関係な一般水辺風景 |
| 0006 神社寺院・歴史 | 木、石、経年の光、静けさ。金色に依存しない品位 | 実在文化財や宗教施設の外観を連想させ、広告物件と混同しやすい | 特定史跡を模写しない格子・石・光の**素材情景**と抽象建築スケッチ |
| 0007 都市夜景・交通 | 帰路の時間、窓の点光、線と暗部の編集 | 暗部のインク潰れ、交通の数字・路線名の虚構、画像上の文字 | 架空の都市通り薄暮、夜の窓明かり、歩行者のいない抽象的光跡 |
| 0008 ポスト・路地・小設備 | 小さな赤い一点、街の細部を主役へ昇格する表現 | ポスト画像が実在する地点の証拠と誤認される恐れ、地図/数値の混在 | 固有所在地を示さない赤い郵便ポストの情景、路地の線画、建築の小ディテール |

原画像の分類はPR #37の候補manifest（REF0003/0004はChatGPT生成概念画の切出し、REF0005〜0008はプログラム編集モック）。制作クオリティ・印刷性はまだユーザー受入完了ではない。

**暫定利用区分**
- REF全体：参考ギャラリー・構図比較・デザイン会議に使用できる。
- REF内の無文字領域のcrop：臨時プロトタイプとしては候補。ただし文字が周囲に混じらないか、被写体が切れていないか、解像度・権利を**独立確認**した場合のみ。自動的にART昇格しない。
- 文字/地図を消すinpainting：見栄えを改善する*別画像の再生成*であり、元画像の文字なし原本を復元したとは扱わない。仕上げ再審査と原画追跡が必要。
- REF全体をA4広告として出す：参考モックの印刷プレビューのみ。完成商品と称さず、架空の数値・誤字・地図を含むと明記する。

### 参考画像の解像度と印刷

A4縦の外形210×297mmへ原画全体を貼る場合、768×1024は横約93ppi/縦約88ppi、1536×2048は横約186ppi/縦約175ppi。いずれも300ppi目標より低い。**PRINT03の画像採否は実際の掲載枠mmから短辺側の実効ppiで判定する**。画素を補間拡大しても元情報の解像力が増えたとは扱わない。コンセプト一覧の中の小さな写真だけを切るとさらに不足しやすい。

## 3. 新しい画像生成依頼を3つの成果物に分ける

### JOB A：完成広告REFの造形研究（少数・探索用）

- 目的：これまでの上下段の完成度の高いアイデア出し。数値・架空キャッチコピーを含めてもよいが、参考資料であることがわかる形にする。
- 一回の成果：完成一覧シート1点（または独立広告紙面案）＋レシピMD＋採否／欠点＋関連タグ。内容は正確な実店舗の宣伝ではない。
- 注意：画像内の文字・地図・販売数字を「本番で差し替え可能な部品」と数えない。図版の美しさ・視線誘導・画風のバリエーションを選別する。
- 制作点数：まず2シートを評価し、似すぎた案は増やさない。下段も上段と同じ水準でレビューする。

### JOB B：文字ゼロの単独ART素材（本番合成候補）

- 目的：JOB Aの写真・線画部分の魅力を、本当に差し込める**別の原画**として再制作する。
- **1回の生成 = 1場面・1画風・1ファイル**。コラージュ、複数コマ、完成広告レイアウト、額縁、テーブル、地図、販売札、ラベルを作らない。
- **画像内の可読文字は一切不可**：看板、背表紙の書名、ロゴ、物件名、駅名、価格、フロア案内、車両番号、郵便ポストの標示、描き込みのラベルを含めない。避けられない領域は無地・背面・抽象形へ。画像制作上どうしても文字らしい模様が出れば不採用か修正して再審査。
- 一意の物件や実際の観光施設の複製を避け、架空の建築・一般化した情景にする。
- テキスト安全領域（例：左側30%を明るくする、右下は何も置かない）と焦点（focalPoint, object-position）を撮影指示として定める。
- 配置枠が145×95mmで300ppiを狙うときの最小必要画素は概ね1713×1122。余裕のある原画（例：横3000px級）を優先。ただしアプリに出すのはIMG-PIPEで作った用途別最適版。
- 生成AIの一回の出力解像度の上限が不足する場合は高解像度再生成や、原本を保持したうえでの画像処理・印刷用採否の実測を行う。**300dpiと名付けるだけで合格にはしない**。

### JOB C：RECIPE / 動的広告の組版（画像生成とは別の工程）

- Markdown＋機械可読な構図JSONで見出し、詩、施設番号、地図、コピー、注記、写真枠、印刷の改ページ条件を記述する。
- HTML/CSS/SVGで実装。**文字、価格、間取り、施設名、距離、地図を写真画像に焼き込まない**。
- 現行PRINT03のPresentationData制約と品質規格を保持。販売価格・間取り・徒歩時間は現行モードで自動生成しない。実在POIの施設名は検証済みデータからのみ。
- ユーザーが「完成広告画像を見たい」と依頼した場合も、JOB Bで原画を独立生成した後、JOB Cによる合成結果（PNG/PDF）をプレビューとして出すことで再現性を担保する。JOB Aは編集方針の参考として残す。

## 5. JOB B：そのまま制作セッションへ渡す共通プロンプト

> APP-003「POÈME / ESTATE」の広告に後から差し込める、**文字のない独立した創作情景画像を1枚**作成してください。対象：{テーマ}、用途：{print_hero / ink_streetscape / support}、必要な画角：{例 3:2}、光と素材：{記述}、視点：{記述}。架空の日本の建築・都市情景で、特定の実在マンションや実在POIの外観を複製しないこと。**1場面・1ファイルのみ。広告、雑誌誌面、UI、複数のカード、分割コラージュ、地図、文字、数字、看板、ロゴ、販売情報、駅名、ポストの地名表示、引用文、透かしを一切含めない。** 将来別レイヤーで文章を置くので、{左30%など}の余白を空け、主題の焦点が切れないトリミング余地を設ける。画像自体への販促コピーの挿入は不可。生成後は日本語・英語・数字に似た画素、遠近法、窓枠、手すり、照明、重複した被写体、著名建築の模倣、実在POIと取り違えそうな描写をチェックし、品質審査を記録してください。画像生成とPR統合・アプリ公開は別承認です。

**望ましくない出力への再指示**：
- 複数広告の誌面が生成された → その画像をJOB A参考として保留し、**JOB Bの単一シーン**を別生成。
- 文字が写っている → 見せ場を損なわないよう本来文字が不要な視点へ変え、別生成。
- 実在施設そのものに見える → 一般化した架空建築へ変更。「架空建築イメージ」の注記はWeb側に設ける。
- 解像度が不足 → 使う枠と実効ppiを先に測り、条件を満たす原画を作る。使えない場合はSVGに戻す。

## 6. 安定して大量運用するための品質ゲート

| ゲート | 判定する内容 | 不合格時 |
|---|---|---|
| G0 目的 | REFなのかARTなのかを生成前に指定したか | 役割を確定して依頼し直す |
| G1 単一素材 | ARTが単一シーン・1枚、写真と文面の一体化なし | REF保留または再制作 |
| G2 文字・ロゴ | ART内に文字/数字/地図/ロゴ/ポスター枠等の混入なし | 使用不可。再制作・再審査 |
| G3 独創性 | 実在物件に偽装していない、重複・単なる色替えでない | 画角・被写体・主役を差別化 |
| G4 画質 | 遠近法・被写体・素材・文字置き余白・掲載枠でのppi | 問題箇所を修正。低ppiはfallback |
| G5 事実分離 | 施設名・距離・地図など実地理を画像から推定していない | 位置データの表示側へ分離 |
| G6 権利・公開 | 生成原本の由来、許諾、公開範囲、モデル提供条件が記録済み | 本番ART候補ではなく保留 |
| G7 再現記録 | assetId、原画hash、プロンプト、画角、採否、使うslotがリンクできる | manifestに仮登録のみ |
| G8 結合QA | HTML/CSS/SVG上に配置しても文字欠け・位置不一致・旧生成トークン汚染なし | PRをDraftに戻すか採用保留 |

自動画像解析だけに品質判定を委ねない。人手での**少数の意図的な視覚確認**が重要。ただし過剰に全画素・全例外をテストせず、まず代表3素材と3構図でPoCする。

## 7. 推奨作業順序

1. 現在の6 REFと評価・manifest候補をPR #37で保持し、画像7点のGitHub登録実体を同PRの最新HEADで照合。PNGがGitHub未登録ならGitHub済としない。
2. この契約を画像制作セッションへ共有し、REFの追加試作を続ける場合も、同じテーマの独立ARTをまず**3点**先行制作する。6テーマすべての原画100点を先に作らない。
3. 最初に実装へ接続するのは\`editorial.facade_split\`の\`print_hero\`1点。PRINT03・IMG-00・IMG-PIPEの既存PR差分を確認してから専用PRで合成する。
4. 文字なしARTの単独試作品についてA4の配置サイズでppiを検証し、印刷版・画面版の比較PNG/PDFを作る。元のREFと最終HTML版の視覚的な同等性を審査。
5. 完成度と実機表示が十分なら、タグに基づくREF/RECIPE選定→ART選定へ拡張。30〜100点制作は、その後にテーマの偏りや重複を監査しながら段階的に。

## 8. 変更の境界

この文書自体は**表示アプリの機能を変更しない**。GitHubに保存したMDは制作指示として使えるが、MDだけでは「実際に画像を再編集可能になった」ことを意味しない。**GitHub保存・原画作成・権利審査・本番広告利用・A4印刷検査・iPhone実機検収をそれぞれ区別**する。新規画像制作セッションが別に進んでいる場合、向こうの既存成果を破棄せず、次バッチからJOB B規則を適用する。これまでのREFは参考資産として残す。
