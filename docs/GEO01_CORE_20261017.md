# GEO-01｜微細設備の正規化と線地物の最近接距離

2026-10-17 JST / APP-003 / 状態：GEO-01 core実装、GEO-02のライブ検索追加は未実施。

## この作業の位置づけ

ユーザーからの「特定要素への過剰検証を避け、全体を進める」という方針に従い、SAFE-01のPS-01〜28を再テストするのではなく、実際の施設選択・広告表示につながる**小さな地理契約**を先に整える。既存630フック・117広告文・LOCATION表示を流用し、APIの検索対象は拡大しない。

### 今回の実装

- **分類**：OSMの `amenity=post_box`, `man_made=manhole`, `highway=traffic_mirror`, `waterway=ditch/drain`, `tunnel=culvert + waterway` を明示タグから識別。culvertを一般排水路より優先。
- **無名地物**：該当する設備だけ `名称未登録` を明記した一般種別ラベルを作成。正式名称にはせず `sourceName: null` と区別し、OSM `type/id` を本人確認の鍵とする。同種・同名のポストが40m以内に2個あっても合体させない。
- **線地物**：現物の `geometry` 内の各線分への最短直線距離を計算。名前付きの大きな川や公園など旧系統は既存挙動を保持。ditch/drain/culvertの `way` がgeometryなしでcenterしか返さない場合は近さの断定を避けて不採用。
- **既存の広告経路**：正規化したPOI → SAFE-01判定 → 既存POEM辞書 → 既存LOCATIONカード・根拠タグを再利用。住所が未収録なら未収録、徒歩経路情報がなければ分数なし。
- **不変範囲**：OpenPOIデータの正規化、既存のOSM公園・図書館・駅等の分類、THE REALITYの独立処理、コピー文言の中身、配信ワークフロー。

### 最低限のテスト計画

追加は代表的な**6件の回帰テスト**のみ。OSM匿名ポストのID非衝突、無名公園の保留、線の中心点と最近接点の差、culvertの分類、geometry欠損時の安全な保留、モックAPIからLOCATIONまでの一連の表示を確認する。PS-01〜28の追加網羅テストはしない。

**重要**：モックで表示される暗渠・郵便ポストは架空のfixtureであり、中野に現物がある証拠ではない。実APIの取得成功と公開ブラウザ・スマートフォン実機の確認を別々に扱う。

### 次の1操作

GEO-02着手前に、提供元の利用条件・障害状況と実データ取得可否を限定リクエストで再確認。失敗すればfixtureの範囲を越えて公開クエリを拡大しない。取得できたOSMの実`type/id`とタグ・geometryを用いた小さなfixtureで、検索→表示まで繋ぐ。
