# GEO-02｜微細設備の明示選択検索・負荷制御

2026-10-17 JST / APP-003 / 非ローカルWeb優先 / 実装PRの作業記録

## 選択理由（ミクロ／マクロ）

目的は既存の630ポエムフックと117組のLOCATION広告文を**現実の都市設備へ接続する**こと。SAFE-01のPS項目や見た目だけの数値を増やさず、取得⇒正規化⇒安全判断⇒広告表示の経路を先に整える。POEM-01の文章文字列は独立作業領域のため変更しない。

**本PRの変更**：

- 既存の通常生成は変更なし。新しいチェックボックス「街の小さな設備も探す」を初期OFFにする。
- 利用者が明示的にONにし、生成ボタンを押した場合のみ、選択地点周辺450mの微細設備を**1 HTTP POST**で照会（郵便ポスト、マンホール、カーブミラー、側溝、排水路、`tunnel=culvert`付き水路）。
- Overpass QL：タイムアウト12秒、サーバーメモリ上限16MiB、出力要素上限42（node最大22 / culvert way最大8 / ditch/drain way最大12）。形状はwayだけ取得し、nodeは最小限の属性と座標を取得。
- クライアントの通信タイムアウト7.5秒・キャンセル・座標単位の**15分間タブ内キャッシュ／失敗時クールダウン**。無限再試行・ページ常駐監視なし。最大8キー保管。
- 取得成功／該当なし／障害／未検索の状態を区別。該当なしは「地域に設備が存在しない」とは表示しない。
- GEO-01の匿名設備、線分最近接距離、SAFE-01の採用制御を通し、既存LOCATION HIGHLIGHTS、THE EVIDENCEの表示へつなぐ。
- データ取得先が利用できないときも通常の広告生成を維持。徒歩分数・施設固有住所・歴史・施設名を創作しない。
- 通常生成時に余計なAPI呼出しが増えないこと、ON時1回、再生成でキャッシュ再使用、障害時の正常系継続を代表テストで確認。

## 公開API依存と未達成条件

前のGEO-00で中野350mはHTTP 502、GEO-01で別インスタンスの限定照会はHTTP 500。よって本PRのOSM例は**fixtureのみ**。中野の暗渠・ポストが実際に存在・取得できたとは主張しない。

[Overpass運用資料](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) は、公開インスタンスを多数の外部アプリの恒久バックエンドに用いることを避けるよう説明している。小さな実験としての運用を超える場合は利用規約・負荷・可用性、静的な地域別データセット、キャッシュ配信、小規模バックエンドまたはセルフホスト等を比較する。単なる日次目安を商用/大衆向けの保証無料枠と見なさない。

## 進捗％の算出規則（暫定）

**マクロ**：計画書13段階（PLAN-00からRELEASE-01）を等重みのマイルストーンとして、`達成段階＋明確に部分達成した段階の0.5` を13で割る。全製品の性能・完成度を意味しない。GEO-00は実データ取得未了で0.5、GEO-02はUI/fixtureまでの段階で0.5とする。よって本PRの実装・CIが通れば `(PLAN1+SAFE1+GEO00 0.5+GEO01 1+GEO02 0.5)/13 ≈31%`。GEO-02の実データ受入に成功したときのみ1.0へ。

**ミクロ（GEO-02）**：設計・通信制限25％、実装25％、fixture/CI25％、取得できた現物のOSM type/id・場所・実ブラウザ受入25％、の4つを各25％として算出。PR CI後は最大75％、実POIの取得と公開画面の受入を確認するまでは100％にしない。

数字は残り時間や正確な工数推定ではない。未確認の各ゲートは残件として明記する。
